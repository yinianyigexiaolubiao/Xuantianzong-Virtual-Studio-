# Post-Canon Locked Overrides / V1.6.1 后置锁定覆盖规则

## 结论

`玄天宗世界设定总纲 V1.6.1` 仍是 **BASE_WORLD_CANON / 基础世界唯一母本**。

但 V1.6.1 自身要求“所有新资产必须回写参数 JSON 和资产索引”。2026-08-07 在 V1.6.1 生成之后，项目继续完成了若干由用户明确总审/锁定的专业资产模块。若这些后置模块与 V1.6.1 的旧字段冲突，则采用以下规则：

> **后置、明确、用户批准且标记 LOCKED 的模块，只在其明确锁定字段范围内覆盖 V1.6.1；其余世界设定仍服从 V1.6.1。**

这不是允许任意附件覆盖总纲，而是把后续正式资产制作视为对 V1.6.1 的受控增量修订。

## 冲突判定门槛

后置模块只有同时满足以下条件才可形成 override：

1. 创建/批准时间晚于当前基础母本；
2. 有明确 `LOCKED`、`用户总审通过`、`用户明确确认锁定` 或同等批准证据；
3. 明确声明 source of truth / lock scope；
4. 覆盖范围可被精确列举，不能泛化到整个世界；
5. 不与更晚的同域 LOCKED 模块冲突；
6. 临时提示词、单张图、REVIEW 文件、AI 推断不能形成 override。

## 工程执行规则

1. `V1.6.1` 是基础世界母本，不得降级成普通历史稿。
2. 若命中 `post_canon_overrides.json` 中的字段，使用 override source。
3. override 只覆盖列出的字段；禁止“因为神兽后来改过，所以其他世界参数也自动改”。
4. 新的 post-canon LOCKED 资产必须同时登记：
   - `MASTER_ASSET_REGISTRY_2026-08-08.md/json`
   - `post_canon_overrides.json`（仅当确有冲突时）
5. 若新资产只是新增而不是冲突，登记为 scoped locked asset，不创建 override。
6. REVIEW、DRAFT、概念图、提示词永远不能自动产生 override。
